# 🎮 원딜러 WonDealer

> “원하는 걸 DEAL 하다”

게임 아이템·게임머니·계정을 거래하고, 실시간 경매와 채팅으로 판매자와 구매자를 연결하는 웹 서비스입니다.

**5인 팀 프로젝트를 홍유나의 개인 포트폴리오로 정리한 통합 저장소**입니다. 프론트엔드와 백엔드를 한곳에서 확인할 수 있으며, 홍유나의 개인 담당은 **백엔드 회원·인증 기능**입니다.

## 프로젝트 개요

## 홍유나 담당 업무

- 회원가입: 이메일 인증, 이메일·아이디·닉네임 중복과 필수 약관 동의 검증
- 로그인: 아이디·이메일 로그인, 팀의 JWT/Security 인증 기반과 연결
- 이메일 인증: 인증 메일 발송, UUID 토큰 확인·만료 처리
- 구글 OAuth: 외부 사용자와 내부 회원·소셜 계정 연결
- 마이페이지: 내 정보·비밀번호·계좌 변경, 본인의 판매·거래·입찰 내역 조회
- 계정 복구: 아이디 찾기·마스킹, 임시 비밀번호 발급·메일 발송

JWT/Security 공통 인프라와 상품·경매·결제·채팅, 프론트 화면 전체는 팀의 담당 범위입니다. 회원 기능의 구현 파일·API·상세 설정은 [백엔드 기술 안내](backend/README.md)에 있습니다.

## 실행 방법

Java 17·MySQL·Node.js를 준비하고, [백엔드](backend/README.md)에서 DB·JWT·메일·OAuth 등의 설정을 먼저 확인합니다.

통합 저장소 루트에서 각각 별도 터미널로 실행합니다.

```powershell
# 터미널 1 · 백엔드
cd backend
.\gradlew.bat bootRun
```

```powershell
# 터미널 2 · 프론트엔드
cd frontend
npm install
npm start
```

화면은 `http://localhost:3000`, 서버는 `http://localhost:8111`입니다.

## 확인 범위

이전 포트폴리오 정리에서는 프론트 프로덕션 빌드와 공개 화면·테마 전환을 확인했습니다. 백엔드 빌드·DB·메일·결제·OAuth의 전체 연동은 미검증입니다. 이번 통합에서는 파일 보존과 문서·이미지 링크를 확인하며, 전체 서비스 실행을 새로 검증한 것은 아닙니다.

## 프로젝트 회고

### 로그인 인증 이후 회원 조회가 실패하던 문제

회원 로그인 기능을 구현하면서 인증에 사용하는 값과 회원을 조회하는 값이 서로 다르다는 문제가 있었습니다. 공통 인증 구성의 UserDetails는 회원의 숫자 ID를 이름으로 반환했지만, 제가 작성한 로그인 서비스에서는 authentication.getName()을 사용자가 입력하는 아이디 문자열로 생각하고 findByUsername()에 전달했습니다. 이 상태에서는 인증 이후 회원 조회 단계에서 잘못된 기준으로 검색해 “회원을 찾을 수 없습니다” 오류가 발생할 수 있었습니다.

인증 객체가 만들어지는 과정까지 확인한 뒤, 반환값을 회원 ID로 변환하고 findById()로 조회하도록 수정했습니다. 같은 “아이디”라는 표현도 로그인 입력값, DB의 회원 ID, 인증 객체의 식별자를 가리킬 수 있다는 점을 놓쳤던 것이 원인이었습니다. 이 경험을 통해 팀원이 만든 공통 인증 구조를 사용하는 기능은 반환값의 의미까지 확인해야 한다는 점을 배웠습니다.

관련 변경: [로그인 회원 조회 기준 수정](https://github.com/pyyzzz/wondealer-backend/commit/e007f6cb16cc3db2f33e09fe7fc44bd39741e0c4)

### 가입 전에 이메일을 인증할 수 있도록 처리 순서 변경

이메일 인증도 처음에는 가입된 회원을 조회한 뒤 인증 메일을 보내는 구조였습니다. 하지만 실제 가입 흐름은 이메일 인증을 먼저 완료하고, 개인정보 입력과 약관 동의를 거쳐 가입하는 방식이었습니다. 기존 구현으로는 아직 회원이 없는 사용자의 이메일을 조회하면서 요청이 거절되므로, API가 화면의 진행 순서를 지원하지 못했습니다.

인증 메일 발송을 회원 객체에서 분리해 이메일 주소만으로 요청하도록 바꾸고, 이미 가입된 이메일은 중복 검사로 차단했습니다. 인증 링크에서는 토큰과 만료 시간을 확인한 뒤 이메일 인증 기록을 저장하고, 최종 가입 시 해당 이메일의 최신 인증 완료 여부를 확인하도록 변경했습니다. 필수 약관 검증과 회원 저장 이후에는 생성된 회원 ID를 사용해 지갑을 생성하도록 순서를 정리했습니다.

개별 API를 먼저 만들고 나중에 연결하면 이런 순서 문제가 생길 수 있다는 점을 느꼈습니다. 가입 전후에 어떤 데이터가 존재해야 하는지부터 정리했더라면 서비스 구조를 다시 바꾸는 작업을 줄일 수 있었을 것입니다.

관련 변경: [가입 전 이메일 인증과 회원·지갑 생성 순서 변경](https://github.com/pyyzzz/wondealer-backend/commit/da12f7e970f7bbdccf05572e0f5dd89ce5cc90e7)

### 앞으로 보완할 부분

앞으로는 회원 가입·인증·로그인의 상태와 식별자 의미를 API 문서에 먼저 정리하고, 프론트엔드와 요청 순서를 맞추고 싶습니다. 인증하지 않은 이메일로 가입하는 경우, 토큰이 만료된 경우, 중복 이메일, 필수 약관 미동의, 로그인 이후 회원 조회 실패까지 통합 테스트로 남기겠습니다. 코드 수정에 그치지 않고 사용자 화면에서 가입부터 로그인까지 이어지는 흐름을 반복 검증할 수 있도록 개선하고 싶습니다.
